# "Xiandan Kanban" Kanban Application Development - Complete Development Requirements Document

## Document Overview

This document is the complete development requirements specification for the "Xiandan Kanban" kanban application, aiming to provide a comprehensive and unified design and implementation guide for the development team. The document integrates all key modules including project introduction, technology selection, functional requirements, data structure, email reminders, statistical analysis, and UI/UX design to ensure efficient and consistent development work.


---

## 1. Project Introduction

### 1.1 Product Positioning and Core Value

"Xiandan Kanban" is a lightweight, modern web-based online kanban management application designed to provide users with an intuitive and efficient visual task management experience.

- **Core Concept**: Simple and easy to use, efficient collaboration, visual management.
- **Core Value**:
    - **Simple and Intuitive**: Adopts a light blue theme and full-screen adaptive layout, providing a clean and comfortable visual experience.
    - **Flexible and Efficient**: Supports multi-board management, task drag-and-drop, custom columns, and batch operations to optimize workflow.
    - **Smart Collaboration**: Enhances collaboration efficiency through automated email reminders, comment @ notifications, and team member management.
    - **Data-Driven**: Provides rich statistical panels and data analysis functions to help teams gain insights into work progress and efficiency.

### 1.2 Target User Groups

- **Primary Users**: Product managers, developers, freelancers, student teams, and startups in small to medium-sized teams.
- **User Characteristics**:
    - Have strong needs for efficiency tools but prefer lightweight, zero-learning-curve tools.
    - Value user experience and interface aesthetics.
    - Have cross-device synchronization needs (desktop, mobile).

## 2. Technology Selection

To ensure development efficiency, system performance, and user experience, we have selected the following technology stack:

### 2.1 Overall Technical Architecture

Adopts a modern web application architecture with front-end and back-end separation. The back-end service is completely based on the Supabase BaaS platform, and the front-end interacts with the back-end through APIs.

```
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│   Frontend (React)  │────│ Supabase API/SDK │────│  PostgreSQL DB  │
└─────────────────┘    └──────────────────┘    └─────────────────┘
         │                       │                       │
         ▼                       ▼                       ▼
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│ Edge Functions  │    │  Supabase Auth   │    │ Supabase Realtime│
│  (Business Logic) │    │   (User Auth)     │    │  (Real-time Sync) │
└─────────────────┘    └──────────────────┘    └─────────────────┘
```

### 2.2 Frontend Technology Stack

- **Core Framework**: **React 18+** & **TypeScript 5.0+**
- **Build Tool**: **Vite 4.0+**
- **UI Framework**: **Tailwind CSS 3.0+**, combined with **Headless UI** to achieve highly customizable components.
- **State Management**:
    - **Zustand**: Used for managing lightweight global state (such as user information, UI state).
    - **React Query**: Used for managing server-side state (data fetching, caching, synchronization).
- **Drag and Drop**: **@dnd-kit/core** provides modern, high-performance drag-and-drop experience.
- **Routing**: **React Router v6**
- **Chart Components**: **Recharts** for data visualization.
- **Code Standards**: ESLint, Prettier, Husky, Conventional Commits.

### 2.3 Backend Technology Stack (Supabase)

- **BaaS Platform**: **Supabase** as the core backend.
- **Database**: **PostgreSQL 15+**, utilizing its powerful query capabilities and RLS (Row Level Security) features.
- **Authentication Service**: **Supabase Auth**, supporting email/password, OAuth third-party login, and JWT management.
- **Real-time Sync**: **Supabase Realtime**, achieving real-time updates of kanban data through WebSocket.
- **Serverless Functions**: **Supabase Edge Functions** (Deno runtime), used for handling complex business logic such as email sending, scheduled tasks, and statistical calculations.
- **File Storage**: **Supabase Storage**, used for storing user avatars, task attachments, and other files.
- **Scheduled Tasks**: **Supabase Cron Jobs**, used for scheduling periodic tasks (such as sending weekly reports, updating statistics).

### 2.4 Deployment and Operations

- **Frontend Deployment**: **Vercel** or **Netlify**, achieving CI/CD automated deployment and global CDN acceleration.
- **Backend Services**: **Supabase Cloud**, providing stable and scalable backend infrastructure.

## 3. Functional Requirements

### 3.1 User Authentication System

Based on Supabase Auth implementation, providing secure and convenient user authentication flow.

- **User Registration**:
    - Supports email and password registration.
    - Sends verification email to activate account.
    - Automatically creates default kanban and guides user after successful registration.
- **User Login**:
    - Supports email/password login and mainstream OAuth providers (such as Google/GitHub) login.
    - Implements "Remember Me" function to maintain login state through Refresh Token.
- **Password Reset**:
    - Users can receive password reset links via email.
- **User Profile**:
    - Users can edit their nickname, avatar, and preference settings (such as theme, email notification switch).

### 3.2 Board & Column Management

- **Multi-board Management**:
    - Users can create, edit, delete, and view their board list.
    - Can choose preset templates when creating boards (such as agile development, content planning).
- **Full-screen Adaptive Layout**:
    - Boards adopt horizontal scrolling layout, with column width adapting to screen size.
    - Supports sidebar collapse/expand to maximize available space.
- **Column Management**:
    - Automatically creates "To Do", "In Progress", "Completed" three default columns when creating new boards.
    - Users can add, edit, and delete custom columns.
    - **Supports drag and drop to adjust column order**, changes are saved in real-time and synchronized.

### 3.3 Task Management (Task/Card)

Tasks are the core elements of the kanban, providing rich management functions and smooth interaction experience.

- **Task Creation (CRUD)**:
    - Can quickly create tasks under specified columns.
    - Supports setting title, description, priority, due date, labels, assignee, etc. for tasks.
- **Task Drag and Drop**:
    - **Intra-column Drag**: Users can drag task cards within the same column to adjust their priority order.
    - **Inter-column Drag**: Supports dragging task cards from one column to another to update task status. After successful operation, the system automatically saves and triggers real-time notifications.
- **Task Details**:
    - Clicking on task cards opens a modal displaying and editing all detailed information of the task.
    - Supports Markdown format task descriptions.
    - Supports adding attachments and posting comments.
- **Batch Operations**:
    - Supports multi-select for batch moving, archiving, or deleting tasks.

### 3.4 Team Collaboration

- **Member Invitation**: Board creators can invite members to join via email or sharing links.
- **Permission Management**:
    - Supports multiple roles (such as owner, admin, member, observer).
    - Role-based permission control ensures data isolation at the database level through PostgreSQL's RLS policies.
- **Real-time Sync**:
    - Any modifications to the kanban by members (such as task movement, content updates) are synchronized to all online members in real-time through Supabase Realtime.
- **Comments and @ Notifications**:
    - Users can post comments under tasks.
    - Supports `@` specific members in comments, who will receive email and in-app notifications.

## 4. Data Structure Recommendations

Database design is based on PostgreSQL, fully utilizing its features. All tables will enable RLS policies to ensure data security.

### 4.1 Core Table Structure (ERD)

```

                               |                        |

                         +---------------+      +----------------+
                         |     tasks     |----<|   attachments  |
                         +---------------+      +----------------+
                               |
                               v
                         +---------------+
                         |   activities  |

```

### 4.2 Main Table Definitions

#### `users` (User Information Table)
Stores basic authentication information of users, managed by Supabase Auth.

#### `user_profiles` (User Profile Table)
```sql
CREATE TABLE user_profiles (
  id UUID REFERENCES auth.users(id) PRIMARY KEY,
  full_name TEXT,
  avatar_url TEXT,
  theme TEXT DEFAULT 'light', -- 'light' or 'dark'
  email_notifications BOOLEAN DEFAULT true,
  -- Other preference settings
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `boards` (Board Table)
```sql
CREATE TABLE boards (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  owner_id UUID REFERENCES auth.users(id) NOT NULL,
  name TEXT NOT NULL,
  description TEXT,
  color TEXT DEFAULT '#3B82F6',
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `board_members` (Board Members Table)
```sql
CREATE TABLE board_members (
  board_id UUID REFERENCES boards(id) ON DELETE CASCADE,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  role TEXT DEFAULT 'member', -- 'owner', 'admin', 'member'
  PRIMARY KEY (board_id, user_id)
);
```

#### `columns` (Column Configuration Table)
```sql
CREATE TABLE columns (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  board_id UUID REFERENCES boards(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  position INTEGER NOT NULL, -- Column order
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `tasks` (Task Table)
```sql
CREATE TABLE tasks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  board_id UUID REFERENCES boards(id) ON DELETE CASCADE,
  column_id UUID REFERENCES columns(id) ON DELETE SET NULL,
  creator_id UUID REFERENCES auth.users(id),
  assignee_id UUID REFERENCES auth.users(id),
  title TEXT NOT NULL,
  description TEXT,
  priority TEXT DEFAULT 'medium', -- 'low', 'medium', 'high', 'urgent'
  due_date TIMESTAMP WITH TIME ZONE,
  position INTEGER NOT NULL, -- Task order in column
  is_completed BOOLEAN DEFAULT false,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `reminders` (Reminder Settings Table)
```sql
CREATE TABLE reminders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  task_id UUID REFERENCES tasks(id) ON DELETE CASCADE,
  reminder_time TIMESTAMP WITH TIME ZONE NOT NULL,
  is_sent BOOLEAN DEFAULT false,
  -- Other reminder-related fields
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 4.3 Security Policies (Row Level Security)

- **Core Principle**: Users can only access data they belong to or are authorized to access.
- **Implementation**:
    - Enable RLS for core tables such as `boards`, `columns`, `tasks`.
    - Create security functions like `is_board_member(board_id, user_id)` to simplify policy definition.
    - **Example Policies**:
        ```sql
        -- Users can only view boards they are members of
        CREATE POLICY "Board members can view boards" ON boards
        FOR SELECT USING (
          is_board_member(id, auth.uid())
        );

        -- Task access permissions are inherited from their parent board
        CREATE POLICY "Task access based on board membership" ON tasks
        FOR ALL USING (
          is_board_member(board_id, auth.uid())
        );
        ```

## 5. Email Reminder Process Design

Implement a highly automated email reminder system through Supabase Cron Jobs and Edge Functions.

### 5.1 Overall Process

```
┌────────────────┐   ┌──────────────────┐   ┌────────────────┐   ┌─────────────┐
│  Cron Job      │──>│  Edge Function   │──>│  Query DB      │──>│  Call Email │
│ (Scheduled)     │   │ (e.g., send-reminders) │   │ (Get pending   │   │ API (e.g.,  │
└────────────────┘   └──────────────────┘   └────────────────┘   │ Resend)     │
                                                                  └─────────────┘
```

### 5.2 Reminder Types and Trigger Mechanisms

- **Task Assignment Notification**: Immediately triggers Edge Function to send email when a task is assigned to a member.
- **Comment @ Notification**: Immediately triggers Edge Function to send email when a user is `@` mentioned in a comment.
- **Due Date Reminder**:
    - **Scheduled Task**: Uses Cron Job to run daily.
    - **Logic**: Queries all incomplete tasks that will expire within 24 hours.
    - **Execution**: Calls email sending service for each eligible task.
- **Daily/Weekly Summary**:
    - **Scheduled Task**: Uses Cron Job to run at fixed times daily or weekly.
    - **Logic**: Edge Function aggregates task completion status, team dynamics, etc. within a specified time range.
    - **Execution**: Generates HTML report and sends to relevant members.

### 5.3 Email Template Design

All emails adopt responsive HTML design to ensure good reading experience on various devices.

- **Template Variables**: Use placeholders (such as `{{user_name}}`, `{{task_title}}`) to dynamically fill content.
- **Key Templates**:
    - **Task Reminder Email**: Contains task title, due date, priority, and direct link.
    - **Weekly Report Email**: Contains statistical information such as task completion rate, status distribution chart, team member performance, etc.
    - **Invitation Email**: Contains inviter information and button to accept invitation.

## 6. Statistical Panel Design Points

The statistical panel is the core of data-driven decision-making and will implement rich chart displays on the front-end through the Recharts library.

### 6.1 Key Performance Indicators (KPIs)

- **Task Metrics**:
    - **Completion Rate**: (Number of completed tasks / Total number of tasks) * 100%
    - **Overdue Rate**: (Number of overdue tasks / Total number of tasks) * 100%
    - **Average Completion Time**: Average time taken for tasks from creation to completion.
- **Team Metrics**:
    - **Member Load**: Number of tasks currently assigned to each member.
    - **Member Efficiency**: Task completion rate per member per unit time.
- **Project Health**:
    - A comprehensive score combining project activity, task completion rate, and overdue status.

### 6.2 Data Visualization Design

- **Dashboard**:
    - Overview cards displaying core data such as total tasks, today's completions, overdue tasks, etc.
- **Chart Types**:
    - **Bar Chart**: Used to display task quantity distribution across different columns or members.
    - **Line Chart/Area Chart**: Used to display time trends of task creation and completion quantities.
    - **Pie Chart/Donut Chart**: Used to display task priority distribution.
    - **Radar Chart**: Used for comprehensive evaluation of team members' performance across multiple dimensions such as workload, efficiency, and completion rate.
- **Data Sources**:
    - Front-end directly calls PostgreSQL **database views (VIEW)** or **functions (FUNCTION)** created in Supabase to obtain pre-calculated statistical data for improved performance.

## 8. Example Code and Standards

### 8.1 Drag and Drop Function Implementation Example (dnd-kit)

```typescript
// React Component for a Kanban Column
import { useSortable } from '@dnd-kit/sortable';
import { CSS } from '@dnd-kit/utilities';

function KanbanColumn({ id, children }) {
  const {
    attributes,
    listeners,
    setNodeRef,
    transform,
    transition,
  } = useSortable({ id });

  const style = {
    transform: CSS.Transform.toString(transform),
    transition,
  };

  return (
    <div ref={setNodeRef} style={style} {...attributes} {...listeners}>
      {children}
    </div>
  );
}
```

### 8.2 Edge Function Example (Sending Email)

```typescript
// supabase/functions/send-email/index.ts
import { serve } from 'https://deno.land/std/http/server.ts';
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2';

serve(async (req) => {
  try {
    const { to, subject, body } = await req.json();
    
    // Call email service (e.g., Resend)
    const res = await fetch('https://api.resend.com/emails', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${Deno.env.get('RESEND_API_KEY')}`,
      },
      body: JSON.stringify({
        from: 'Xiandan Kanban <noreply@xiandan.com>',
        to,
        subject,
        html: body,
      }),
    });

    if (!res.ok) {
        throw new Error('Failed to send email');
    }

    return new Response(JSON.stringify({ message: 'Email sent successfully' }), { status: 200 });
  } catch (error) {
    return new Response(JSON.stringify({ error: error.message }), { status: 500 });
  }
});
```
