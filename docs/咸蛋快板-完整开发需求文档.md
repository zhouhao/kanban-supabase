## 1. 项目简介

### 1.1 产品定位与核心价值

"咸蛋快板"是一款基于Web的轻量级、现代化的在线看板管理应用，旨在为用户提供直观、高效的可视化任务管理体验。

- **核心理念**: 简洁易用、高效协作、可视化管理。
- **核心价值**:
    - **简洁直观**: 采用淡蓝色主题和全屏自适应布局，提供清爽、舒适的视觉体验。
    - **灵活高效**: 支持多看板管理、任务拖拽、自定义列和批量操作，优化工作流程。
    - **智能协作**: 通过自动化邮件提醒、评论@通知和团队成员管理，提升协作效率。
    - **数据驱动**: 提供丰富的统计面板和数据分析功能，帮助团队洞察工作进展和效率。

### 1.2 目标用户群体

- **主要用户**: 中小型团队的产品经理、开发人员、自由职业者、学生团队及初创公司。
- **用户特征**:
    - 对效率工具有强烈需求，但偏好轻量级、无学习成本的工具。
    - 重视用户体验和界面美观。
    - 有跨设备同步（桌面、移动端）的需求。

## 2. 技术选型

为保证开发效率、系统性能和用户体验，我们选用以下技术栈：

### 2.1 整体技术架构

采用前后端分离的现代化Web应用架构，后端服务完全基于Supabase BaaS平台，前端通过API与后端进行数据交互。

```
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│   前端应用 (React)  │────│ Supabase API/SDK │────│  PostgreSQL DB  │
└─────────────────┘    └──────────────────┘    └─────────────────┘
         │                       │                       │
         ▼                       ▼                       ▼
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│ Edge Functions  │    │  Supabase Auth   │    │ Supabase Realtime│
│  (业务逻辑)      │    │   (用户认证)      │    │  (实时同步)      │
└─────────────────┘    └──────────────────┘    └─────────────────┘
```

### 2.2 前端技术栈 (Frontend)

- **核心框架**: **React 18+** & **TypeScript 5.0+**
- **构建工具**: **Vite 4.0+**
- **UI 框架**: **Tailwind CSS 3.0+**，搭配 **Headless UI** 实现高度可定制的组件。
- **状态管理**:
    - **Zustand**: 用于管理轻量级的全局状态（如用户信息、UI状态）。
    - **React Query**: 用于管理服务端状态（数据获取、缓存、同步）。
- **拖拽功能**: **@dnd-kit/core** 提供现代化、高性能的拖拽体验。
- **路由管理**: **React Router v6**
- **图表组件**: **Recharts** 用于数据可视化。
- **代码规范**: ESLint, Prettier, Husky, Conventional Commits。

### 2.3 后端技术栈 (Backend - Supabase)

- **BaaS 平台**: **Supabase** 作为核心后端。
- **数据库**: **PostgreSQL 15+**，利用其强大的查询能力和 RLS (Row Level Security) 特性。
- **认证服务**: **Supabase Auth**，支持邮箱/密码、OAuth第三方登录和JWT管理。
- **实时同步**: **Supabase Realtime**，通过WebSocket实现看板数据的实时更新。
- **无服务器函数**: **Supabase Edge Functions** (Deno运行时)，用于处理邮件发送、定时任务、统计计算等复杂业务逻辑。
- **文件存储**: **Supabase Storage**，用于存储用户头像、任务附件等文件。
- **定时任务**: **Supabase Cron Jobs**，用于调度周期性任务（如发送周报、更新统计数据）。

### 2.4 部署与运维

- **前端部署**: **Vercel** 或 **Netlify**，实现CI/CD自动化部署和全球CDN加速。
- **后端服务**: **Supabase Cloud**，提供稳定、可扩展的后端基础设施。

## 3. 功能需求

### 3.1 用户认证系统

基于Supabase Auth实现，提供安全、便捷的用户认证流程。

- **用户注册**:
    - 支持邮箱和密码注册。
    - 发送验证邮件激活账户。
    - 注册成功后，自动创建默认看板并引导用户。
- **用户登录**:
    - 支持邮箱/密码登录和主流OAuth提供商（如Google/GitHub）登录。
    - 实现"记住我"功能，通过Refresh Token维持登录状态。
- **密码重置**:
    - 用户可通过邮箱接收密码重置链接。
- **用户资料**:
    - 用户可以编辑自己的昵称、头像和偏好设置（如主题、邮件通知开关）。

### 3.2 看板与列管理 (Board & Column)

- **多看板管理**:
    - 用户可以创建、编辑、删除和查看自己的看板列表。
    - 创建看板时可选择预设模板（如敏捷开发、内容规划）。
- **全屏自适应布局**:
    - 看板采用水平滚动布局，列宽根据屏幕尺寸自适应。
    - 支持侧边栏收起/展开，最大化可用空间。
- **列管理**:
    - 新建看板时自动创建 "待办"、"进行中"、"已完成" 三个默认列。
    - 用户可添加、编辑、删除自定义列。
    - **支持拖拽调整列的顺序**，变更实时保存并同步。

### 3.3 任务管理 (Task/Card)

任务是看板的核心元素，提供丰富的管理功能和流畅的交互体验。

- **任务创建 (CRUD)**:
    - 可在指定列下快速创建任务。
    - 支持为任务设置标题、描述、优先级、截止日期、标签、负责人等。
- **任务拖拽**:
    - **列内拖拽**: 用户可以在同一列内拖拽任务卡片，以调整其优先级顺序。
    - **跨列拖拽**: 支持将任务卡片从一个列拖拽到另一个列，以更新任务状态。操作成功后，系统自动保存并触发实时通知。
- **任务详情**:
    - 点击任务卡片可打开模态框，显示并编辑任务所有详细信息。
    - 支持Markdown格式的任务描述。
    - 支持添加附件和发表评论。
- **批量操作**:
    - 支持通过多选对任务进行批量移动、归档或删除。

### 3.4 团队协作

- **成员邀请**: 看板创建者可以通过邮箱或分享链接邀请成员加入。
- **权限管理**:
    - 支持多种角色（如所有者、管理员、成员、观察员）。
    - 基于角色的权限控制，通过PostgreSQL的RLS策略在数据库层面保证数据隔离。
- **实时同步**:
    - 任何成员对看板的修改（如任务移动、内容更新）都会通过Supabase Realtime实时同步给所有在线成员。
- **评论与@通知**:
    - 用户可以在任务下发表评论。
    - 支持在评论中`@`特定成员，被@的成员将收到邮件和应用内通知。

## 4. 数据结构建议

数据库设计基于PostgreSQL，充分利用其特性。所有表都将启用RLS策略以确保数据安全。

+---------------+      +-------------------+      +----------------+

+---------------+      +-------------------+      +----------------+
                               |                        |
                               v                        v
                         +---------------+      +----------------+
                         |     tasks     |----<|   attachments  |
                         +---------------+      +----------------+
                               |
                               v
                         +---------------+
                         |   activities  |

### 4.2 主要表定义

#### `users` (用户信息表)
存储用户的基本认证信息，由Supabase Auth管理。

#### `user_profiles` (用户资料表)
```sql
CREATE TABLE user_profiles (
  id UUID REFERENCES auth.users(id) PRIMARY KEY,
  full_name TEXT,
  avatar_url TEXT,
  theme TEXT DEFAULT 'light', -- 'light' or 'dark'
  email_notifications BOOLEAN DEFAULT true,
  -- 其他偏好设置
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `boards` (看板表)
```sql
CREATE TABLE boards (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  owner_id UUID REFERENCES auth.users(id) NOT NULL,
  name TEXT NOT NULL,
  description TEXT,
  color TEXT DEFAULT '#3B82F6',
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `board_members` (看板成员表)
```sql
CREATE TABLE board_members (
  board_id UUID REFERENCES boards(id) ON DELETE CASCADE,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  role TEXT DEFAULT 'member', -- 'owner', 'admin', 'member'
  PRIMARY KEY (board_id, user_id)
);
```

#### `columns` (列配置表)
```sql
CREATE TABLE columns (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  board_id UUID REFERENCES boards(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  position INTEGER NOT NULL, -- 列的顺序
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `tasks` (任务表)
```sql
CREATE TABLE tasks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  board_id UUID REFERENCES boards(id) ON DELETE CASCADE,
  column_id UUID REFERENCES columns(id) ON DELETE SET NULL,
  creator_id UUID REFERENCES auth.users(id),
  assignee_id UUID REFERENCES auth.users(id),
  title TEXT NOT NULL,
  description TEXT,
  priority TEXT DEFAULT 'medium', -- 'low', 'medium', 'high', 'urgent'
  due_date TIMESTAMP WITH TIME ZONE,
  position INTEGER NOT NULL, -- 任务在列中的顺序
  is_completed BOOLEAN DEFAULT false,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### `reminders` (提醒设置表)
```sql
CREATE TABLE reminders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  task_id UUID REFERENCES tasks(id) ON DELETE CASCADE,
  reminder_time TIMESTAMP WITH TIME ZONE NOT NULL,
  is_sent BOOLEAN DEFAULT false,
  -- 其他提醒相关字段
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 4.3 安全策略 (Row Level Security)

- **核心原则**: 用户只能访问他们所属或被授权访问的数据。
- **实现**:
    - 为 `boards`, `columns`, `tasks` 等核心表启用RLS。
    - 创建`is_board_member(board_id, user_id)`等安全函数来简化策略定义。
    - **示例策略**:
        ```sql
        -- 用户只能查看他们作为成员的看板
        CREATE POLICY "Board members can view boards" ON boards
        FOR SELECT USING (
          is_board_member(id, auth.uid())
        );

        -- 任务的访问权限继承自其所属的看板
        CREATE POLICY "Task access based on board membership" ON tasks
        FOR ALL USING (
          is_board_member(board_id, auth.uid())
        );
        ```

## 5. 邮件提醒流程设计

通过Supabase Cron Jobs和Edge Functions实现高度自动化的邮件提醒系统。

### 5.1 整体流程

```
┌────────────────┐   ┌──────────────────┐   ┌────────────────┐   ┌─────────────┐
│  Cron Job      │──>│  Edge Function   │──>│  查询数据库      │──>│  调用邮件API  │
│ (定时触发)      │   │ (e.g., send-reminders) │   │ (获取待提醒任务) │   │  (e.g., Resend) │
└────────────────┘   └──────────────────┘   └────────────────┘   └─────────────┘
```

### 5.2 提醒类型与触发机制

- **任务指派通知**: 任务被分配给某个成员时，立即触发Edge Function发送邮件。
- **评论@通知**: 评论中`@`用户时，立即触发Edge Function发送邮件。
- **截止日期提醒**:
    - **定时任务**: 使用Cron Job每日运行一次。
    - **逻辑**: 查询所有在24小时内即将到期的未完成任务。
    - **执行**: 为每个符合条件的任务调用邮件发送服务。
- **每日/每周总结**:
    - **定时任务**: 使用Cron Job在每天或每周固定时间运行。
    - **逻辑**: Edge Function聚合指定时间范围内的任务完成情况、团队动态等。
    - **执行**: 生成HTML报告并发送给相关成员。

### 5.3 邮件模板设计

所有邮件都采用响应式HTML设计，确保在各种设备上都有良好的阅读体验。

- **模板变量**: 使用占位符（如 `{{user_name}}`, `{{task_title}}`）动态填充内容。
- **关键模板**:
    - **任务提醒邮件**: 包含任务标题、截止日期、优先级和直达链接。
    - **周报邮件**: 包含任务完成率、状态分布图、团队成员绩效等统计信息。
    - **邀请邮件**: 包含邀请人信息和接受邀请的按钮。

## 6. 统计面板设计要点

统计面板是数据驱动决策的核心，将通过Recharts库在前端实现丰富的图表展示。

### 6.1 关键统计指标 (KPIs)

- **任务指标**:
    - **完成率**: (已完成任务数 / 总任务数) * 100%
    - **逾期率**: (逾期任务数 / 总任务数) * 100%
    - **平均完成时间**: 任务从创建到完成的平均耗时。
- **团队指标**:
    - **成员负载**: 每位成员当前负责的任务数量。
    - **成员效率**: 每位成员在单位时间内的任务完成率。
- **项目健康度**:
    - 一个综合评分，结合了项目活跃度、任务完成率和逾期情况。

### 6.2 数据可视化设计

- **仪表盘 (Dashboard)**:
    - 概览卡片，展示总任务数、今日完成、逾期任务等核心数据。
- **图表类型**:
    - **柱状图**: 用于展示不同列或不同成员的任务数量分布。
    - **折线图/面积图**: 用于展示任务创建与完成数量的时间趋势。
    - **饼图/环形图**: 用于展示任务优先级的分布情况。
    - **雷达图**: 用于综合评估团队成员在工作量、效率、完成率等多个维度的表现。
- **数据来源**:
    - 前端直接调用在Supabase中创建的PostgreSQL**数据库视图(VIEW)**或**函数(FUNCTION)**来获取预计算好的统计数据，以提升性能。

### 8.2 Edge Function 示例 (发送邮件)

```typescript
// supabase/functions/send-email/index.ts
import { serve } from 'https://deno.land/std/http/server.ts';
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2';

serve(async (req) => {
  try {
    const { to, subject, body } = await req.json();
    
    // 调用邮件服务 (e.g., Resend)
    const res = await fetch('https://api.resend.com/emails', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${Deno.env.get('RESEND_API_KEY')}`,
      },
      body: JSON.stringify({
        from: '咸蛋快板 <noreply@xiandan.com>',
        to,
        subject,
        html: body,
      }),
    });

    if (!res.ok) {
        throw new Error('Failed to send email');
    }

    return new Response(JSON.stringify({ message: 'Email sent successfully' }), { status: 200 });
  } catch (error) {
    return new Response(JSON.stringify({ error: error.message }), { status: 500 });
  }
});
```

- [ ] 看板滚动和任务拖拽时，帧率是否保持稳定？
- [ ] 大数据量（如超过1000个任务）下，看板性能是否可接受？（应采用虚拟滚动等优化）

- [ ] 所有数据表是否都配置了恰当的RLS策略？

- [ ] Edge Function的调用是否进行了权限验证？
- [ ] 敏感信息（如API密钥）是否通过环境变量安全管理？
